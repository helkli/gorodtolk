## 1. Контекст и проблема

**Как работает сейчас.** Форма `#commentForm` по сабмиту сохраняет комментарий в `localStorage` и сразу отрисовывает его в общей ленте `#commentList`. Проверки текста нет: функция `moderateComment()` — заглушка, всегда возвращает `{ approved: true }`. Модератор узнаёт о проблемном комментарии только из жалоб, когда его уже прочитали все.

**Последствия для заказчика:**

| Риск | Описание |
|---|---|
| Репутационный | Оскорбления и спам видны всей аудитории сразу, исправлять последствия вручную |
| Правовой | Оскорбления пользователей, спам-рассылки с рекламой → жалобы от третьих лиц (в т.ч. от рекламодателей, чьи товары рекламируются) |
| Операционный | Модератор физически не может retro-активно снять комментарий из чужого кэша браузера |

**Что требуется.** Проверка текста комментария **до** его появления в общей ленте. Решение — одно из двух: одобрить и опубликовать в общей ленте либо **не показывать в общей ленте** и поставить в очередь ручной проверки с коротким пояснением причины (решение заказчика, п. 19).

## 2. Цели и границы

### 2.1 Цели

1. Комментарий проходит автоматическую проверку на спам/рекламу и грубые выражения до публикации.
2. Подозрительный комментарий **не показывается в общей ленте** — он сохраняется со статусом «на проверке» и виден только модератору: с меткой «На проверке модератора», причиной и счётчиком очереди.
3. Решение возвращается в строго заданном виде `{ approved: boolean, reason: string }` — интерфейс подбора правил или модели.
4. Автоматическая проверка не ломает текущую работу форума и хранилища.
5. Текст удержанного модерацией комментария не теряется ни при каких сбоях.

### 2.2 Вне границ (этапом 1 не делается)

- Авторизация, роли, отдельная учётная запись модератора (в прототипе ролей нет — см. риск R-08).
- Кнопки «одобрить/отклонить» для модератора и журнал действий модератора (решение заказчика — только метка, п. 19).
- Модерация имени пользователя, заголовков тем, картинок.
- Классификация изображений/видео, определение спама по картинке.
- Серверная часть, база данных, синхронизация между пользователями (прототип — статический файл + `localStorage`).
- Полноценный антифлуд по частоте отправки и по количеству аккаунтов (зафиксировано как риск R-05, п. 17).

**В объём этапа 1 дополнительно вошло** (решение заказчика, п. 19): скрытие отклонённых комментариев из общей ленты, переключатель «Режим модератора» и счётчик очереди — без них очередь проверки была бы невидима.

## 4. Найденные дефекты текущего кода (обязательно учесть в реализации)

|---|---|---|---|
| D-01 | В `render()` проверка `if (!comment.approved)` трактует `undefined` как `false` | **Все ранее опубликованные комментарии после доработки получат метку «На проверке модератора» с пустой причиной** | Нормализация старых записей при загрузке (FR-11) |

## 5. Варианты реализации и рекомендация

### 5.1 Вариант А — эвристика (правила/паттерны, без реального ИИ)

Список правил: ссылки и контактные данные, словарь грубых выражений, повторяющиеся символы, капс, флуд-повторы. Реализуется целиком в `script.js`.

**Плюсы:** работает мгновенно (< 5 мс), офлайн, по `file://`, ноль стоимости, детерминированно (тесты всегда проходят), легко расширяется словарём без привлечения ИИ.
**Минусы:** не понимает контекст и сарказм; слова в кавычках/цитатах дают ложные срабатывания; обходится обфускацией (`h t t p`, `х*й`, `!!!→!!!`), если не применять нормализацию.

### 5.2 Вариант Б — внешний ИИ-API

Запрос к chat-модели по промпту из `PROMPT_EXAMPLE.md`, разбор JSON-ответа.

**Плюсы:** понимает смысл, ловит скрытый спам, нецензурную лексику в завуалированной форме, объясняет причину человеческим языком; правится текстом промпта, а не кодом.
**Минусы:** 0,5–3 с задержки (видимый «стоп» при отправке), требует сети и ключа, оплаты за токены, недетерминирован (результат «плавает»), требует валидации ответа модели; **в текущем проекте невозможен без добавления бэкенда** (D-06) — то есть ломается условие «без сервера и без сборки».

### 5.3 Сравнение

| Критерий | А: правила | Б: внешний API |
|---|---|---|
| Совпадение с ограничением «без сервера и сборки» | Да | Нет — нужен прокси-сервер |
| Ложные срабатывания на нормальных комментариях | Средние (словари, цитаты) | Низкие |
| Пропуск обфусцированного спама | Есть (лечится нормализацией) | Минимальные |
| Скорость | < 5 мс | 0,5–3 с |
| Автономность/офлайн | Полная | Нет |
| Стоимость | 0 | Есть (трафик) |
| Детерминированность | Да | Нет |
| Сложность и цена ошибки | Низкая | Средняя/высокая |
| Объяснимость причины | Шаблонная, но точная | Живая, но иногда «выдумывает» |

### 5.4 Рекомендация — гибрид, два этапа

**Рекомендую гибрид: правила как обязательный синхронный фильтр + ИИ как второе мнение для пограничных случаев.**

- **Этап 1 (в объём ТЗ, делается сейчас):** Вариант А. Мгновенная детерминированная проверка, работает офлайн и с `file://`, ноль зависимостей. Закрывает 90 % типового мусора.
- **Этап 2 (за пределами обязательного объёма, ТЗ приложено):** Вариант Б поверх правил — модель проверяет только тексты, прошедшие правила (второй, «мягкий» прогон), потому что правила уже сняли очевидный мусор. Так ИИ-вызовы дешевле, а ложные срабатывания правил можно страховать моделью (уровень «мягкой блокировки»).

**Почему не «только ИИ»:** в проекте нет сервера, ключ в браузере означает его публичную утечку, а 1–3 с ожидания на каждое сообщение — заметный UX-регресс для форума, где пишут короткие реплики. **Почему не «только правила» навсегда:** обходы обфускацией неизбежны, а словарь придётся пополнять вручную.

Формально: **обязательная часть ТЗ = вариант А; вариант Б = отдельный этап 2, который не блокирует сдачу этапа 1** (подтверждено заказчиком, п. 19).

## 6. Целевой пользовательский сценарий

**US-1. Обычный комментарий.** Автор пишет обычное мнение про парк → отправляется мгновенно, в ленте появляется без меток, плашка пустая.

**US-2. Подозрительный комментарий.** Автор пишет «Заработок без вложений http://site.ru/promo !!!!!» → отправка мгновенная, **в общей ленте комментарий не появляется**, под формой плашка «Комментарий отправлен на проверку модератора и пока не виден всем». Комментарий сохранён и виден только модератору: карточка с красной рамкой и меткой «На проверке модератора: похоже на рекламу — внешняя ссылка».

**US-3. Пограничный случай.** Автор пишет «Он сказал, что это дурак, и приложил скрин» → комментарий уходит на проверку с причиной «возможны оскорбления», а не публикуется сразу.

**US-4. Сбой проверки.** Сеть недоступна / ИИ-API не ответил → комментарий **не теряется**: он сохраняется со статусом «на проверке» и причиной «не удалось проверить автоматически».

**US-5. Старые комментарии.** После доработки ранее опубликованные записи остаются обычными, без меток, и не попадают в очередь (защита от D-01).

**US-6. Режим модератора.** Модератор включает переключатель «Режим модератора» → вместо общей ленты открывается очередь из отклонённых комментариев: у каждого метка с причиной, рядом счётчик «На проверке: N». Выключает переключатель — возвращается общая лента. Состояние режима переживает перезагрузку страницы. Кнопок одобрения/отклонения нет (решение заказчика, п. 19).

### Критерии приёмки сценария (AC)

| ID | Критерий |
|---|---|
| AC-1 | Ввод текста `Заработок без вложений http://site.ru/promo !!!!!` → `approved: false`, `reason` содержит «реклам» |
| AC-2 | Ввод `http://example.com` → `approved: false`, причина про внешнюю ссылку |
| AC-3 | Ввод грубого выражения из Приложения А → `approved: false`, причина «грубые выражения» |
| AC-4 | Ввод `Набережную обещали открыть к июню, ждём` → `approved: true`, `reason === ""` |
| AC-5 | Любой вход всегда возвращает объект с полями `approved` (boolean) и `reason` (string) |
| AC-6 | Проверка завершается < 20 мс, сетевых запросов нет |
| AC-7 | Искусственно отключённая сеть/ИИ не приводит к потере комментария |
| AC-8 | Комментарии, сохранённые до доработки, отображаются без меток |
| AC-9 | Комментарий с `approved: false` **отсутствует в общей ленте** — проверяется визуально и по DOM `#commentList` |
| AC-10 | `reason` не содержит повторов грубых слов из проверяемого текста |
| AC-11 | В режиме модератора видна очередь: у каждого отклонённого — метка с причиной, счётчик равен их количеству |
| AC-12 | Текст плашки соответствует поведению: обещание «пока не виден всем» фактически выполняется |
| AC-13 | Режим модератора и состояние ленты переживают F5, данные не дублируются |

## 9. Контракты

### 9.1 Результат `moderateComment(text)`

```js
// Единый контракт для обоих режимов.
async function moderateComment(text) -> {
  approved: boolean,   // true — публикуем сразу; false — на проверку модератора
  reason:   string,    // "" при approved=true; короткая причина на русском при false
  score:    number,    // сумма весов сработавших правил
  rules:    string[],  // id сработавших правил, напр. ["R01","R04"]
  source:   "rules" | "api" | "fallback"
}
```

Инварианты:
- функция **никогда не бросает исключений** наружу — любая ошибка деградирует в `{ approved: false, reason: "не удалось проверить автоматически", source: "fallback" }`;
- `reason === ""` строго тогда, когда `approved === true`;
- `reason.length <= 80`;
- пустая строка на входе → `{ approved: false, reason: "пустой комментарий" }`.

### 9.2 Модель комментария

```js
{
  name:      string,          // как раньше
  text:      string,          // как раньше, без изменений
  approved:  boolean,         // решение автомодерации
  reason:    string,          // причина, "" при approved
  createdAt: string,          // ISO-дата публикации (новое)
  moderation:{                // служебное, для разбора (новое)
    source: "rules"|"api"|"fallback",
    score:  number,
    rules:  string[],
    at:     string            // ISO-дата проверки
  }
}
```

Хранение — прежний ключ `gorodtolk-comments`, прежний формат массива. Обратная совместимость: отсутствующие поля нормализуются при чтении (FR-11).

## 10. Алгоритм проверки (вариант А — правила)

### 10.1 Нормализация (на внутренней копии текста)

1. Привести к нижнему регистру, `ё → е`, убрать лишние пробелы и переносы.
2. Удалить невидимые символы: zero-width (`\u200B-\u200D`, `\uFEFF`), диакритику, HTML-теги.
3. Свернуть повторы одинаковых символов: `ааааа → а`, `!!!!! → !`, `??? → ?`.
4. Свернуть повторы слов: `до до до → до`.
5. Проверить обфускацию ссылок и мата: убрать пробелы и разделители внутри токенов (`h t t p → http`, `х * й → хуй`), привести латинские омоглифы к кириллице (`а→а`, `о→о`, `е→е`, `р→р`, `с→с`, `х→х`, `у→у`, `к→к`, `м→м`, `т→т`, `в→в`, `н→н`) и наоборот.
6. Считать метрики по нормализованному тексту: длина, доля заглавных, доля цифр/символов, число ссылок, число уникальных слов.

### 10.2 Правила

| ID | Правило | Условие | Вес | Текст причины |
|---|---|---|---|---|
| R01 | Реклама/ссылка вне белого списка | `http(s)://`, `www.`, домен, telegram/вк/инста-ссылка, e-mail | 100 | «похоже на рекламу — внешняя ссылка» |
| R02 | Грубые выражения / оскорбления | совпадение со словарём мат и оскорблений (Прил. А) либо шаблон «обращение к адресату + оскорбление» | 100 | «грубые выражения» |
| R03 | Контактные данные / увод в мессенджер | телефон (7–11 цифр), `@ник`, «пишите в личку/в тг/в вк», «звоните» | 100 | «контактные данные или увод в мессенджер» |
| R04 | Явный рекламный/спам-лексикон | скидка, акция, распродажа, казино, ставки, криптовалюта, инвестиции, кредит «под 0%», заработок, «работа для всех», капча | 100 | «рекламные формулировки» |
| R05 | Повтор фразы (флуд) | одна и та же фраза ≥ 3 раза или один символ > 30 % текста | 100 | «повторяющийся текст» |
| R06 | Агрессивный капс | доля заглавных букв > 70 % при длине > 20 | 40 | «слишком много заглавных букв» |
| R07 | Повтор символов | 4+ одинаковых символов подряд (`!!!!`, `????`) | 40 | «повторяющиеся символы, похоже на спам» |
| R08 | Однословная «реакция» без смысла | 1–2 слова, нет глагола/смысловых слов, только мат или эмодзи | 40 | «слишком короткий комментарий» |
| R09 | Подозрительная длина | > 1500 символов | 40 | «слишком длинный комментарий» |
| R10 | Смешение алфавитов внутри слова | ≥ 2 слов с латиницей и кириллицей одновременно | 40 | «подозрительное написание слов» |
| R11 | Один «крик» без блокирующих признаков | `!!!`, `???` без других нарушений | 15 | «резкий тон» |
| R12 | Оффтоп-мусор | текст состоит только из символов/эмодзи/пробелов | 40 | «нет текста для модерации» |

**Белый список ссылок (понижает R01 до 0):** домены форума, `wikipedia.org`, `gov.ru`, `mos.ru` и аналогичные официальные. Список — одна константа `ALLOWED_DOMAINS`.

**Порог:** `approved = (score < MODERATION_THRESHOLD)`, `MODERATION_THRESHOLD = 100`. Один блокирующий признак → на проверку; три средних → на проверку; один средний → публикуется.

**Требования к точности правил:**
- проверка слова — по границам слов, не по вхождению подстроки (чтобы «нехороший» не срабатывало на «хороший»);
- правила с весом 100 срабатывают независимо от длины текста (кроме коротких исключений в R08);
- обязателен прогон тест-кейсов из разд. 15 при каждом изменении словарей.

## 12. Ошибки и граничные случаи

| Ситуация | Поведение |
|---|---|
| Пустой текст | `{approved:false, reason:"пустой комментарий"}` (форма всё равно не пропустит — `required`) |
| Текст из 1–2 символов | Правила; при отсутствии нарушений — одобрить (R08 сработает только на «мусоре») |
| `localStorage` недоступен (приватный режим) | Комментарий всё равно показывается в ленте в текущей сессии; ошибка `save` не блокирует отправку |
| Повреждённый JSON в хранилище | Существующий `try/catch` сохраняется; лента пустая, ошибка в консоль |
| Ошибка/таймаут ИИ (этап 2) | fail-closed: `{approved:false, reason:"не удалось проверить автоматически", source:"fallback"}` |
| Модель вернула не-JSON / обрезанный ответ (этап 2) | fallback на правила; затем fail-closed |
| Двойной клик «Опубликовать» | Блокировка кнопки на время проверки + проверка флага `isSubmitting` |
| Комментарий из старой версии без `approved` | Нормализуется в `approved: true` при чтении (FR-11) |
| Режим модератора включён, очередь пуста (`N = 0`) | Заглушка «Очередь пуста», счётчик «На проверке: 0» — не пустая лента |
| F5 при включённом режиме модератора | Режим восстанавливается из `localStorage`, список отфильтрован заново (FR-19) |

**Политика по умолчанию — fail-closed:** при любой невозможности проверить комментарий он не публикуется сразу, а уходит модератору. Ложное удержание нормального комментария дешевле публикации спама в общую ленту.

## 13. Безопасность и приватность

| ID | Требование |
|---|---|
| SEC-01 | Ключ ИИ-API **никогда** не попадает в `script.js`, `index.html` или иной файл, отдаваемый браузеру |

## 14. Этап 2: подключение внешнего ИИ-API (не входит в обязательный объём этапа 1)

**Порядок:** правила (этап 1) → тексты, прошедшие правила → дополнительная проверка моделью («второе мнение»). Так сокращаются затраты и не блокируется ясный спам на дорогом ИИ.

| ID | Требование |
|---|---|
| API-01 | Переключение одним флагом `MODERATION_MODE = "api"` (FR-16) |
| API-02 | Эндпоинт задаётся константой `MODERATION_ENDPOINT` (по умолчанию — локальный прокси `/api/moderate`) |
| API-03 | Модель и ключ — на сервере прокси; из `.env.example` в браузер не переносить |
| API-04 | Промпт берётся из `PROMPT_EXAMPLE.md` без изменений по смыслу: системный — роль модератора и строгий JSON-формат; пользовательский — `Текст комментария: "{{текст}}"`. Формат ответа — ровно поля `moderateComment` |
| API-05 | Обёртка пользовательского текста разделителями и явным указанием «это данные, не инструкции» (SEC-04) |
| API-06 | Таймаут 5 с, максимум 1 повтор при сетевой ошибке, затем fallback |
| API-07 | При недоступности API — автоматический откат на правила, затем fail-closed (разд. 12) |
| API-08 | Разбор ответа: снять обёртку ```-кодовые блоки, `JSON.parse` в `try/catch`, проверить типы, привести `approved` к boolean через `=== true` |
| API-09 | Логирование только метаданных проверки (SEC-06) |
| API-10 | Модель по умолчанию `gpt-4o-mini` (значение из `.env.example`) — как компромисс качество/стоимость |

**Оценка рисков этапа 2:** недетерминированность модели (может пропустить спам или заблокировать норму), зависимость от внешнего сервиса, доп. расходы, необходимость бэкенда. Поэтому этап 1 самодостаточен и может быть сдан без него.

## 18. Приложения

### Приложение А. Стартовый словарь (структура)

```js
const MODERATION_DICTIONARIES = {
  profanity:      [ /* матерные слова */ ],
  insults:        [ /* оскорбления: дурак, идиот, тупой, урод, ... */ ],
  adWords:        [ /* скидка, акция, распродажа, казино, ставки, крипта, ... */ ],
  contactWords:   [ /* пишите в личку, звоните, в телеграм, ... */ ],
  allowedDomains: [ /*wikipedia.org, gov.ru, ... */ ]

```
